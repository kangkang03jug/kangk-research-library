# Daily Research Agent

Research Question serialization is mandatory: for an explicit RQ, write the explanation-language (for example, Chinese) wording in `question` and preserve the paper's verbatim wording in `original_question`; for an inferred RQ, write only the explanation-language `question` and set `original_question` to `null`. Keep a concrete source locator for both types. Never translate or invent `original_question`, and never attach it to an inferred question.

Research-question review is mandatory for body-backed papers. For `reading_basis: full_text` or `official_html`, read Introduction/Motivation and record every explicitly labeled RQ as `type: explicit` with its original wording/count and source locator. If no explicit RQ exists but the authors' actual objective/core question can be reliably summarized, you must emit at least one `type: inferred` Research Question with an Introduction/Motivation locator; never leave the array empty just because the paper has no `RQ1`/`RQ2` labels. Only after reviewing those sections may you leave the array empty when no question can be reliably extracted. In that case, both `detail.research_questions_empty_reason` (a specific explanation of why no reliable question can be extracted) and `detail.research_questions_empty_source` (the exact Introduction/Motivation locator reviewed) are mandatory. Set both fields to `null` whenever the array is non-empty. Do not use a generic fallback reason.

Read `config/research-profile.yaml`, all existing files under `data/papers/` and `data/user/`, and today's file under `data/daily/`. Search multiple reliable academic sources using the profile's scope and recent-year window. Prefer quality and relevance; use freshness only as a tie breaker. Check DOI, arXiv ID, OpenReview ID, and normalized title before adding anything.

Reading Basis protocol: Abstract + Metadata is sufficient for Quick Read, but Detail requires body evidence. Before generating Detail, actively try the publisher Full Text, Official HTML, and accessible PDF. Do not stop when an abstract is found if public full text can reasonably be fetched. Set `reading_basis` to `full_text` or `official_html` only after reading Introduction/Motivation, Method, Experiments/Results, and Limitations/Discussion. Use `abstract_only` only after reasonable retrieval attempts fail; state this fallback explicitly and avoid body-level claims. Preserve Section/Page/Table/Figure locators for Contributions, Research Questions, and key results. If no explicit RQ exists, infer one only after reading Introduction/Motivation.

Process exactly one paper per run. If a new, sufficiently good paper exists, verify its metadata, create one canonical paper record and a default user-state record, and add one recommendation. If not, do not force a low-quality addition: recommend one existing high-quality paper that is not deep-read and has not already appeared today. Record the concrete venue/source and reading basis. Use only verified facts; do not infer a venue or ranking. Preserve `my_notes`, `my_tags`, `deep_read`, and `favorite`. Do not follow old preprints for later publication status. For `detail.research_questions`, add `type: explicit` only for questions the paper explicitly labels as RQ / Research Question (such as RQ1 or RQ2), preserving the actual count and a source locator. For every `full_text` / `official_html` record, inspect Introduction/Motivation: if there is no explicit RQ but the authors' objective/core question can be reliably summarized, add at least one `type: inferred` entry; do not mechanically leave the array empty. An inferred question must be labeled in the UI, never rewritten as an original RQ number, and must cite an Introduction/Motivation locator. An empty array is allowed only after the relevant body sections were reviewed and no reliable question can be extracted; then fill both `research_questions_empty_reason` and `research_questions_empty_source` with a specific explanation and the exact locator reviewed, otherwise data validation will fail. Set both empty metadata fields to `null` when any question is present. Never infer from Abstract + Metadata alone. All questions must reflect the authors' actual objective, not AI speculation. Keep author-reported facts separate from AI analysis, and include locators for key claims. Generate `detail.contributions` as 2–5 concrete, evidence-backed contributions (method, system, experiment, dataset, analysis, or finding), each with a source locator when available; do not use generic praise. Write `what_can_be_done_next` only as follow-ups directly tied to this paper's method, experiments, limitations, transferable tasks, or derived research questions—not generic AI advice.

Language is mandatory: generate every AI-authored paper summary and analysis field (`quick_read`, `detail`, research-question explanations, limitation analysis, relation-to-research, and next-step analysis) in `config/research-profile.yaml -> language.explanation`. When it is `zh-CN`, every non-empty field must use natural, concise Chinese suitable for academic reading while retaining standard English research terms, method names, Benchmark names, Metric names, model names, and forms such as `pass@1` where appropriate. Do not mechanically translate sentence by sentence. The bilingual website toggle controls UI labels only: it must never change the paper-body language or cause a second English summary to be generated. Keep `original_abstract` verbatim in its source language, and keep the paper title, authors, venue/source, identifiers, URLs, and BibTeX in their original form.

所有 AI-generated paper summary / analysis 必须按 Research Profile 的总结语言撰写；`zh-CN` 配置下统一使用自然中文，并自然保留英文科研术语、方法名、Benchmark、Metric 和模型名。Original Abstract 保留原文。UI 的 `中文 / EN` 模式不得覆盖这项规则。

Research Questions 规则：`explicit` 只用于论文明确写出的 RQ / Research Question，保留实际数量、原文表述和 source locator。对 `full_text` / `official_html`，必须阅读 Introduction / Motivation；若能可靠概括作者实际研究目标或核心问题，必须至少生成一条 `type: inferred`，不能因没有 `RQ1/RQ2` 而留空。Inferred 必须标记为推断，不伪装成作者编号，并提供 Introduction / Motivation locator。只有阅读相关正文后仍无法可靠提取时才允许空数组；此时必须填写 `detail.research_questions_empty_reason`（具体解释，至少 20 个字符）和 `detail.research_questions_empty_source`（Introduction / Motivation 定位）。RQ 非空时这两个字段都必须为 `null`。Abstract + Metadata 不得作为推断依据，推断必须忠实于作者目标。

Run `npm run validate:data`, relevant tests, and `npm run build`. Commit and push only if every check succeeds. Report the selected paper, whether it was new or existing, venue/source, relevance, and modified files.
