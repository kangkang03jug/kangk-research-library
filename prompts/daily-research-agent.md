# Daily Research Agent

Read `config/research-profile.yaml`, all existing files under `data/papers/` and `data/user/`, and today's file under `data/daily/`. Search multiple reliable academic sources using the profile's scope and recent-year window. Prefer quality and relevance; use freshness only as a tie breaker. Check DOI, arXiv ID, OpenReview ID, and normalized title before adding anything.

Process exactly one paper per run. If a new, sufficiently good paper exists, verify its metadata, create one canonical paper record and a default user-state record, and add one recommendation. If not, do not force a low-quality addition: recommend one existing high-quality paper that is not deep-read and has not already appeared today. Record the concrete venue/source and reading basis. Use only verified facts; do not infer a venue or ranking. Preserve `my_notes`, `my_tags`, `deep_read`, and `favorite`. Do not follow old preprints for later publication status. For `detail.research_questions`, add `type: explicit` only for questions the paper explicitly labels as RQ / Research Question (such as RQ1 or RQ2), preserving the actual count and a source locator. If no explicit RQ exists but the Introduction or Motivation clearly states the research objective, add `type: inferred`; label it as an inferred question in the UI and never rewrite it as RQ1/RQ2. Do not infer questions from Abstract + Metadata alone: if the reading basis does not cover Introduction/Motivation, keep the array empty. Explicit questions must retain a concrete Section / Page / Paragraph source locator; inferred questions should retain one whenever available. All questions must be grounded in the authors' actual objective, not AI speculation. Keep author-reported facts separate from AI analysis, and include locators for key claims. Generate `detail.contributions` as 2–5 concrete, evidence-backed contributions (method, system, experiment, dataset, analysis, or finding), each with a source locator when available; do not use generic praise. Write `what_can_be_done_next` only as follow-ups directly tied to this paper's method, experiments, limitations, transferable tasks, or derived research questions—not generic AI advice.

Language is mandatory: generate every AI-authored paper summary and analysis field (`quick_read`, `detail`, research-question explanations, limitation analysis, relation-to-research, and next-step analysis) in `config/research-profile.yaml -> language.explanation`. When it is `zh-CN`, every non-empty field must use natural, concise Chinese suitable for academic reading while retaining standard English research terms, method names, Benchmark names, Metric names, model names, and forms such as `pass@1` where appropriate. Do not mechanically translate sentence by sentence. The bilingual website toggle controls UI labels only: it must never change the paper-body language or cause a second English summary to be generated. Keep `original_abstract` verbatim in its source language, and keep the paper title, authors, venue/source, identifiers, URLs, and BibTeX in their original form.

所有 AI-generated paper summary / analysis 必须按 Research Profile 的总结语言撰写；`zh-CN` 配置下统一使用自然中文，并自然保留英文科研术语、方法名、Benchmark、Metric 和模型名。Original Abstract 保留原文。UI 的 `中文 / EN` 模式不得覆盖这项规则。

Research Questions 规则：`detail.research_questions` 中每条记录必须有 `type: explicit` 或 `type: inferred`。只有论文明确写出 RQ / Research Question（如 RQ1、RQ2）时才能使用 `explicit`，保留实际数量，不补齐固定数量，并且必须保留非空 `source` 定位；没有显式 RQ、但 Introduction / Motivation 明确表达作者实际要回答的问题时，使用 `inferred`，不得伪装成 RQ 编号，并在有定位时保存 `source`。若 Reading Basis 只有 Abstract + Metadata，不能为了填满字段而推断，保持数组为空。`inferred` 必须忠实于作者研究目标，而不是 AI 自由发挥。 `detail.contributions` 必须记录 2–5 条基于证据的真实贡献（方法、系统、实验、数据集、分析或新发现），能定位时填写 source；`what_can_be_done_next` 只写针对本文方法、实验、局限、迁移任务或新研究问题的后续工作。

Run `npm run validate:data`, relevant tests, and `npm run build`. Commit and push only if every check succeeds. Report the selected paper, whether it was new or existing, venue/source, relevance, and modified files.
